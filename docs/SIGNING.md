# Подпись и обновления «поверх»

Android считает APK обновлением, только если совпадают **три вещи**:

| Что | Как это устроено в проекте |
|---|---|
| `applicationId` | `dev.filedeck.app`, не меняется |
| подпись (сертификат) | один ключ в `android/signing/` — на всех ваших машинах и в CI |
| `versionCode` | считается из версии в `package.json`: major·10000 + minor·100 + patch |

Если не совпало что-то одно, Android пишет «Приложение не установлено» или предлагает удалить старое.

## Какие ключи есть

1. **Общий ключ** — `android/signing/filedeck-sideload.jks` (лежит в git, пароли в `signing.properties`).
   Им подписываются `npm run apk`, запуск из Android Studio и сборки CI. Он публичный: подходит для
   установки «для себя», но **не** для магазина — подписать им «обновление» сможет кто угодно, у кого есть репозиторий.
2. **Личный ключ** — `npm run keygen` создаёт `android/signing/datalaw-upload.jks` и `android/keystore.properties`
   (оба в `.gitignore`). Им подписываются `npm run release` и `npm run aab`. Сделайте **копию в надёжном месте**:
   потеряв ключ, вы не сможете обновлять приложение в магазине.

## Проверка: обновится ли поверх

```bash
npm run doctor            # подключите телефон по USB, включите «Отладку по USB»
```

Скрипт сравнивает отпечаток (SHA-256) ключа, которым будет подписана сборка, с подписью установленного
приложения и пишет прямо: «ОБНОВИТ поверх» или «ПОДПИСИ РАЗНЫЕ». Тот же отпечаток печатается в начале каждой сборки
(`Подпись: … SHA-256 …`) и виден в приложении: **Настройки → О приложении**. Отпечаток общего ключа:

```
DB:51:0F:3E:24:09:94:FF:3D:A3:D6:95:2B:08:AB:9C:E7:EF:7B:C9:07:81:6E:E6:99:40:DD:10:98:17:75:1F
```

## Если «Приложение не установлено»

- **Ранее поставлена версия, собранная другим ключом** (например, 1.0.0 с автоматическим debug-ключом):
  удалите её один раз — `adb uninstall dev.filedeck.app` или вручную. Дальше все обновления идут поверх.
- **Версия на телефоне новее** (versionCode больше): Android запрещает понижение. Поднимите версию `npm run bump`.
- **Сборка из Play и сборка из APK** подписаны разными ключами (Play App Signing): поверх друг друга не ставятся.
- **Файл ключа испорчен в git** (например, перенос строк на Windows): в проекте `.gitattributes` помечает `*.jks` как бинарные;
  не копируйте ключ через текстовые редакторы.

## Правила, чтобы обновления не ломались

1. Не меняйте `applicationId` и не пересоздавайте `android/signing/filedeck-sideload.jks`.
2. Перед каждой сборкой для раздачи — `npm run bump`.
3. Для «себя» собирайте `npm run apk`, для магазина — `npm run release` / `npm run aab` (личный ключ).
   Не смешивайте каналы на одном телефоне без переустановки.
